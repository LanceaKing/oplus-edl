**R1 — strict input contract and existing callers: closed.** Repository-wide call-site inspection found four production calls to `firehose_program_storage`. Erase uses the bounded `zero_input` stream at `cli/src/main.rs:344–357`; overwrite-storage and write use `ProgramInput` at `main.rs:378–395` and `405–441`; rawprogram uses the same adapter at `cli/src/programfile.rs:162–178`. There is no remaining production caller that passes a one-byte erase source or an unpadded file while requesting rounded-up sectors. The write caller checks the rounded sector count against `part.size()` before programming.

`cli/src/input.rs:36–56` checks offset, byte-count overflow, and the selected file range. It permits only less than one final sector of explicit padding. A requested subrange is bounded with `Take<File>`; bytes outside the selected range cannot be transmitted. `input.rs:69–75` preserves unexpected truncation as an I/O error while source bytes remain. It cannot silently substitute permitted padding for newly missing source bytes. `zero_input` at lines 87–88 is finite and uses checked length arithmetic. Rawprogram offset parsing now rejects malformed values and checks multiplication overflow before sending that program command. These changes are necessary caller adaptation, not a new input format or product workflow.

The eight supplied CLI tests exercise production input preparation and the real XML parser with scripted transport. They cover aligned, one-byte, and multi-payload unaligned files; finite multi-payload erase; offset and selected-range behavior; invalid known ranges before any command; truncation after input construction; and missing/negative final ACK. The top-level `main` dispatch is inspected rather than executed. This meets the earlier review's requested “real caller input preparation or XML entry” boundary without requiring hardware or a production test transport abstraction.

**R2 — read refusal classification: closed.** `qdl/src/lib.rs:711–721` retains initial response attributes, and emits `ReadRejected` only for a complete NAK with no `AttemptRestart`/`AttemptRetry` key and absent or exactly `false` `rawmode`. Presence of a hint even with value `0`, malformed/empty `rawmode`, and explicit raw mode all produce an ordinary failure that the documented contract requires callers to stop on. There is no reset, retry, or follow-up write. The type documentation at `qdl/src/types.rs:60–61` states the stopping rule.

The supplied tests at `qdl/tests/firehose_io.rs:368–409` cover plain NAK, explicit false, both hints, zero-valued retry, and true/invalid/empty raw mode. They verify the error classification, empty output, command count and Drop behavior. The plain-refusal test consumes a following queued ACK, establishing that the initial response parser does not over-consume the stream. The mutation regression at lines 670–695 separately preserves `Rejected` for complete hinted initial and final program NAKs. No product best-effort continuation policy is implemented or claimed in this stage.
