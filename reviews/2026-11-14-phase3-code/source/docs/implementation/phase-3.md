# 第三阶段实施记录

日期：2026-11-14。按已通过复审的设计实施第三阶段，未提交、推送或操作设备。公开 restore／flash 仍在枚举和连接前返回 unsupported；unlock／lock 保持不支持。没有实施第四阶段的写入编排、回读比较、最终动作或确认流程。

## 已实现

- `backup::directory`：多 LUN、多分区或全部已列出分区；共用 GPT 捕获和 `.partial` 发布路径。名称不安全或选中项大小写冲突时记录不支持，继续其他可读项。传输失败停止会话，保留已完成项、失败 partial 和已知未尝试项。
- `storage`：共享分区列表、LUN 目录名称及冲突规则。省略 CLI `--lun` 时解析 getstorageinfo 的明确数量；不按连续试读猜测 LUN。当前识别响应属性中的 `num_physical_partitions`、`num_physical`、`bNumberLu`，以及日志 JSON `storage_info.num_physical`。数量缺失、非法或冲突均拒绝；JSON block_size 与配置冲突时拒绝。未识别的设备格式需显式限定 LUN。
- `restore`：无传输依赖的全量映射预检。支持嵌套／平铺目录和单镜像；检查精确名称、唯一目标、普通文件、非空镜像、扇区尾部补零和分区大小，记录未覆盖尾部。目录排除 `.gpt`、`.partial`、其他扩展名和非普通文件；不依赖清单。
- `program_xml`：按 program 文件顺序、节点顺序，再按 patch 文件顺序产生内存候选项。保留 XML 来源和节点号；检查参数、文件、偏移、源区间、已知目标范围及扇区大小。空文件名、零长度 program 和非 DISK patch 记录跳过原因。非空缺失文件始终报错；只有跳过项时报不支持。
- `sparse`：解析 v1.0 RAW、FILL 和 DONT_CARE。仅保存数据文件偏移、填充模式和范围，不把镜像展开到内存。检查头部、chunk 长度、文件边界和展开块数。DONT_CARE 不计入传输字节；未知类型（含 CRC chunk）拒绝，符合固定 qdl 类型范围。

协议表达式保留十进制数、`NUM_DISK_SECTORS` 加减常量和 `CRC32(start,length)`，可带协议常用末尾点；不在主机求值。已知要求本地镜像变换的包由预检调用方显式标记并拒绝，不声称可以自动发现所有依赖。稀疏源偏移非零明确不支持。候选项不是保存计划，也不会执行命令。

全部读取结果仍声明覆盖范围受限。未进入的后续 LUN 没有可用 GPT，因此不会虚构其分区结果；已读取 GPT 的剩余分区记录未尝试。读取失败后不再发送后续读或修改命令。
