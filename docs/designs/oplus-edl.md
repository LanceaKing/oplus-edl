## 概述

开发原生 Rust 命令行工具 `oplus-edl`，支持 Windows、macOS 和 Linux。通过 Sahara 上传加载器，通过 Firehose 备份、恢复和刷写。协议基础采用 qdlrs，在后续创建的 `LanceaKing/qdlrs` fork 中维护必要修正，产品固定引用实际修正提交。产品代码采用 MIT；第三方源码保留原有许可证。

公开入口保持 `unlock`、`lock`、`backup`、`restore`、`flash` 五个工作流，内部自动处理连接和协议阶段。首版实际交付通用备份、恢复和刷写；没有经过验证的机型方法时，unlock／lock 返回不支持。RMX3800 是研究目标，不是通用版本发布前提，也不是已经确认支持的机型。

设计阶段仅修改设计文档。第一阶段进度与证据见[第一阶段实施记录](../implementation/phase-1.md)。作者随后授权第二阶段，固定引用 fork 的 `7e0a31a5be2ab5d01b27bd743ee67a445ad0b84d`；产品实现与离线检查见[第二阶段实施记录](../implementation/phase-2.md)。本次不提交、不推送，设备操作仍不在授权范围内。

第三阶段已按后续授权实施：目录备份、恢复映射、XML 和稀疏镜像离线解析，见[第三阶段实施记录](../implementation/phase-3.md)。第四阶段已按后续授权接通公共写入、验证和停止策略，见[第四阶段实施记录](../implementation/phase-4.md)。未提交、未推送、未操作设备。当前实际依赖修正提交为 `a80cd1e8cd1cd60634b9c5ce9a4c8c96b727c003`。

## 问题与目标

第五阶段已完成，见[第五阶段实施记录](../implementation/phase-5.md)：经后续授权提交并推送产品代码后，GitHub Actions 的 Windows x86_64 MSVC、macOS arm64、Linux x86_64 GNU 四项原生检查全部通过。原生结果与此前交叉编译记录分开保存。未操作设备，第六阶段仍须另行授权。上文第二至第四阶段的未提交／未推送描述保留为历史状态。

第六阶段已按 2026-11-15 的后续授权开始，见[RMX3800 实机记录](../implementation/phase-6-rmx3800.md)。14.1.0.190 原包 loader 和签名分区摘要表已获设备接受；configure 和 getsigndata 获 ACK，分区读取被拒绝并超时，未发送分区写入。产品新增显式 `--signed-digest` 接入，按原样发送表并检查确认后才 configure；该步骤不代替设备会话签名，不扩大为认证绕过或已支持 RMX3800 整包刷写。此前的设备操作授权描述保留为历史状态。

已有工具具备可参考的 EDL 操作路径。首版的任务是将这些路径组织成跨平台 Rust 工作流，修复会造成数据错误、错误成功报告或意外操作的缺陷。首版不建设独立的备份数据库、可审批计划系统或固件证明系统。

具体目标：

- 支持 Sahara 加载、Firehose 配置、读取、写入和必要的固件补丁操作。
- 备份全部已列出的分区或指定分区，每分区保存一个原始镜像，多存储单元分别保存。
- 直接使用普通分区镜像恢复，不要求本工具生成的专用清单。
- 支持 rawprogram／patch XML、原始镜像和 Android 稀疏镜像，行为参照固定版本实现。
- 明确选择目标连接；多设备时不任意选择第一台。
- 保留必要输入和传输检查，如文件存在、数据长度、分区范围、短读短写、协议 ACK／NAK。
- 默认尝试写后回读。无法读取时明确报告“写入已确认、验证未完成”；数据不一致是失败，缺失写入确认是结果未知。
- 区分构建、离线协议测试和实机验证，不用刷写成功推导降级可启动或通用机型支持。

仅使用免费且公开可获取的资源。资源可下载不代表可随工具分发，不默认捆绑未验证加载器。

## 技术方案

```text
五个工作流入口
      |
参数、目标选择、操作摘要与结果
      |
备份 / 恢复 / XML 与稀疏镜像处理
      |
薄 qdlrs 适配层
      |
修正后的 Sahara / Firehose / USB 或串口
```

采用同步调用和有界传输缓冲，不引入异步运行时、插件框架或作业数据库。产品层负责用户流程，fork 负责协议正确性及通用存储能力。只修改复用路径实际需要的接口，不为未来扩展预先重构整个依赖。

### 备份

使用参考工具的存储信息和 GPT 路径列出分区。LUN 表示一个逻辑存储单元。省略 `--lun` 时选择全部已发现单元，指定时只选择该单元。省略 `--partition` 时备份这些单元的全部已列出分区。分区名过滤器选择各单元内的全部同名匹配项，摘要逐项列出 LUN。报告实际扫描范围和失败项。扫描范围受限时只报告已扫描范围成功，不宣称全设备备份成功。

目录形式为 `lun<N>/<partition>.bin`。名称限制、冲突处理和 GPT 文件位置见“目录与分区映射契约”。首版不自动转义名称或添加序号。不能安全命名的项报不支持，其他可读项仍可备份。读取先写同目录 `.partial` 文件。获得完整预期字节和最终 ACK 后，才改为正式文件名。中断文件保留后缀并报告失败，不提供分块日志或自动续作。

已有输出文件不静默覆盖。重新备份由用户指定新目录或显式覆盖所选文件。传输按块进行，但不生成持久化块记录或整套备份清单。

### 恢复

参照 EDL 的 `w`／`wl`：用户指定镜像与目标分区，或从目录中选择分区镜像。不存在的镜像、找不到的分区及超出目标分区的输入报错。目录缺少未选分区不阻止恢复；不要求目录覆盖所有设备分区。

原始镜像短于目标分区时，只写镜像对应范围，显示实际长度和未覆盖尾部；不额外要求源文件等于整分区长度。非整扇区尾部按参考写入路径补零到扇区边界，并检查补齐后仍不超出分区。这不表示补齐了缺失备份，也不能报告整个分区内容已完整恢复。

不要求源设备身份、专用清单、源 GPT 与目标 GPT 完全相同或输入哈希证明。目标分区使用当前设备 GPT 定位。目录恢复使用明确的 LUN 和原分区名，不根据相似名称猜测目标。首次写入前检查全部选中映射。任何映射不唯一时，整次恢复报错且不写入。目录恢复排除 `.partial` 文件和 GPT 捕获文件。

### 固件刷写

按用户指定顺序读取 rawprogram 文件，再处理 patch 文件，文件内部保持节点顺序。以 qdlrs 的参数和协议调用方式为基础，补充 qdl 参考中的稀疏镜像处理。只建立执行所需的内存操作列表，不生成版本化计划或审批文件。

保留基本检查：XML 可解析、操作受支持、必需参数有效、引用文件存在、源区间不越界、已知目标范围不溢出。错误参数不默认为零。未知操作报不支持。没有镜像的空条目单独显示为跳过，不能将用户指定但不存在的非空文件名静默跳过。

RAW 与 FILL 稀疏块产生写入，DONT_CARE 保持跳过；不把跳过区间扩展成零写入。首版以固定 qdl 实现支持的稀疏类型为对齐范围，其他类型明确报不支持，不额外扩展稀疏格式或校验系统。

DISK 补丁沿用协议端支持的 `NUM_DISK_SECTORS` 和 `CRC32(...)` 等表达式，不运行主机脚本，也不建设通用求值器。本地文件补丁列入摘要并跳过，不改原始固件。首版不证明所有跳过项都与 DISK 补丁等价；对于说明或已知流程明确要求先修改本地镜像的包，直接报不支持。未知依赖不自动当作已验证兼容，结果中保留跳过项，文档说明这一限制。

参考实现的启动单元设置保留为明确的 `--set-bootable <lun>` 操作，而不是仅凭分区名自动触发。刷写结束默认不重启；需要重启时通过显式选项执行。两者都在操作摘要中显示，不加入独立的模式编排框架。

### 中断与后续动作

恢复和刷写在首次修改存储前检查全部已知输入错误。运行时，任何写入、DISK 补丁或启动单元设置失败，立即停止后续修改。已发送修改请求但缺少最终确认时，将该项记为结果未知。后续 program、patch、启动单元设置和请求的重启均不执行。保留已完成项，将剩余项记为未尝试。错误处理和对象释放都不能发送 reset，也不自动重试修改操作。

刷写顺序固定为 program、DISK patch、回读验证、可选启动单元设置、可选重启。恢复每个镜像后先验证，再处理下一个镜像。回读不一致会停止剩余动作。读请求被拒绝是否允许继续，由下表决定。传输超时、截断或协议失步后，不继续发送命令，也不自动重连。

### 验证和结果

默认对预期内容已知的写入范围做流式回读比较。恢复的预期内容包括允许的扇区尾部补零。刷写按最终写入顺序确定预期内容，重叠区间归后一次写入。完全被覆盖的项标记 `verification: not_applicable`，原因为 `superseded`。RAW 和 FILL 产生待验证范围。DONT_CARE 自身不产生写入或验证范围，也不删除此前写入的验证范围。

首版不计算 DISK 补丁的写后值。能定位的补丁区间标为未验证，不与补丁前镜像比较。若表达式使补丁位置无法在主机确定，则该 LUN 的写入范围均标为未验证。其他无法确定地址或预期内容的写入也按未验证处理。不为此新增表达式求值器或补丁模拟器。

| 验证模式 | 写入前检查 | 回读与结果 | 后续修改和显式最终动作 |
| --- | --- | --- | --- |
| `best-effort`，默认 | 允许预期内容未知的范围，摘要列出这些范围 | 验证已知范围。读被拒绝或预期内容未知时，结果为验证未完成 | 验证匹配时可继续。验证未完成时，仅允许因预期内容未知，或读请求在原始数据前收到完整 NAK 且会话仍处于命令边界而继续 |
| `required` | 存在预期内容未知的写入时，首次修改前报不支持。首版所有 DISK 补丁均属此情况 | 全部最终仍生效的写入范围必须匹配。运行时拒读或读取失败，结果为验证未完成 | 验证未完成即停止。不得执行剩余写入、启动单元设置或重启 |
| `none` | 不增加验证条件 | 不发回读命令，标记未请求验证。已确认操作可返回成功 | 操作已确认且会话正常时，可以继续 |

三种模式都不能忽略修改操作失败或确认缺失。回读不一致属于执行失败。任何读取超时、断连或协议失步均停止会话，包括 `best-effort`。已取得的写入 ACK 仍保留，不因后续读失败改为未知写入。`required` 不会预先探测设备是否允许读取，故运行时拒读可能发生在写入之后。

验证要求只覆盖 program／patch 形成的存储字节。启动单元设置和重启以各自协议确认判断结果，不声明其内容已经回读验证。

保留以下区别：写入已确认、读取被拒绝或失败、回读不一致、写入确认缺失。后两者分别是确定失败和结果未知，不自动重写。无法回读时明确报告“写入已确认、验证未完成”。回读成功也不表示固件能够启动。

普通文本提供阶段进度和逐项结果。`--json` 的标准输出只包含一个最终结果对象，进度和交互提示写到标准错误。字段、汇总规则和退出类别见“结果契约”。只维护这些必要字段，不新增 JSON schema 套件。

### 解锁、上锁与机型支持

没有可用且经过验证的方法时，unlock／lock 在操作设备前返回不支持。首版不增加 fastboot 集成、认证绕过、UFS provisioning、RPMB、Diag 或内存转储。之后若有具体机型方法，再单独设计其操作步骤。

加载器和固件由用户提供。未知加载器可以按常规 Sahara 流程尝试，协议拒绝就报告失败；不以设备数据库缺少条目为由额外阻断，也不将加载成功扩大为全部功能受支持。

## 备选方案与决定

| 方案 | 本版决定与理由 |
| --- | --- |
| 自建协议栈 | 不采用。复用 qdlrs，减少重复协议实现和测试工作 |
| 封装外部 EDL 可执行程序 | 不采用。外部程序增加跨平台运行时打包和输出解析工作。Rust 库接口便于保留原始错误和控制设备副作用 |
| 在产品内 vendor qdl | 不采用。单独维护 qdlrs fork 可将协议修正与产品流程分开。固定修正提交后，产品依赖无需混入 C 工具构建和适配代码 |
| 原始镜像加专用 JSON 清单与追加日志 | 移出首版。采用普通原始分区镜像，不强制专用格式 |
| 哈希计划审批、身份与布局一致性证明 | 最新范围调整移出首版；保留普通输入、目标和范围检查 |
| 本地镜像补丁副本或等价证明 | 不做；与参考路径一致地显示并跳过，不宣称支持依赖本地变换的包 |
| 不修复参考实现缺陷 | 不采用；输入短读、输出短写、错误成功和意外重置不能作为兼容行为保留 |

## 详细实现计划

### 必要的 qdlrs 修正

以下发现来自固定版本静态检查，尚未通过本次设备测试复现。修正必须附对应离线回归用例，不扩大成无关重构。

| 位置 | 必要修正 |
| --- | --- |
| `firehose_program_storage` | 检查并正确处理输入短读、提前 EOF 和读取错误，不发送未读到的缓冲区内容；传输短写按后端语义处理或明确失败 |
| `firehose_read_storage` | 检查输出完整写入，避免磁盘短写却报告读取成功；零进展或结束不能无限循环 |
| `firehose_read` | 等待命令响应时，日志或部分数据后的超时不能变成 ACK；保留欢迎日志收集与最终响应的区别 |
| `firehose_write`、`firehose_write_getack`、配置响应及 `Drop` | 保留原始失败；错误路径和对象释放不自动重置设备，显式重置仍可调用 |
| `firehose_get_storage_info` | 检查 NAK，不用返回 `Ok(())` 掩盖它；将存储信息提供给调用方，避免产品解析控制台输出 |
| Sahara 镜像请求 | 检查偏移加长度的溢出、镜像边界和设备输入触发的断言，返回错误而不是崩溃 |
| 配置与后端选择 | 处理无效载荷大小，实际刷写不误启用 SkipWrite；提供明确的设备打开路径，不默认选择多设备中的第一台 |
| 日志与进度 | 仅对产品使用路径提供可控输出，避免污染 JSON 结果；不为了统一风格重写所有工具输出 |

产品不能通过错误字符串推断写入结果。fork 在实际使用的修改路径上提供 `MutationFailure`，保留原始错误原因。其确认状态只有三种：`NotSent` 表示确定未发送请求，`Rejected` 表示收到完整 NAK，`Unknown` 表示请求可能已发送但没有完整最终确认。部分命令发送、数据阶段失败和最终 ACK 超时均归 `Unknown`。正常返回表示最终 ACK 已取得。此类型放在 `qdl/src/types.rs`，仅调整受影响调用方，不统一重写所有错误类型。

源码依据：[核心协议](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/lib.rs)、[配置解析](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/parsers.rs)、[设备释放](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/types.rs)、[Sahara](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/sahara.rs)。

### 离线测试边界

本次只读核对了固定提交的测试接入点。`QdlReadWrite` 继承 `BufRead + Write + Send + Sync`。`QdlDevice<T>` 的传输、配置和 `reset_on_drop` 字段均公开。`QdlChan` 为协议函数提供读写与配置访问。[类型定义依据](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/types.rs#L80-L139)

Firehose 写入函数另接收 `Read` 输入，读取函数另接收 `Write` 输出。因此，传输故障与本地文件故障可分别注入。这是源码接口检查，不是设备或构建验证。[存储函数依据](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/lib.rs#L493-L651)

后续实现按以下边界接入测试：

1. 在产品 `tests/support/mod.rs` 和 fork `qdl/tests/support/mod.rs` 中分别实现测试专用 `ScriptedIo`。它实现现有 `QdlReadWrite`，不新增生产传输 trait。脚本包含入站字节片段、EOF、`ErrorKind`，以及每次写调用可接受的字节数或错误。`Read` 与 `BufRead` 共用消费位置。`fill_buf` 不提前消费字节，`consume` 才推进位置。
2. 写端记录实际接受的字节、调用边界、空写和 flush。记录通过共享句柄保留到会话释放后。超时直接返回 `TimedOut`，不依赖真实等待。零进展与 EOF 也由脚本显式触发。脚本耗尽但流程仍请求数据时，测试失败。
3. 用 `QdlDevice<ScriptedIo>` 调用实际 Sahara／Firehose 路径。产品 `src/device.rs` 把“打开设备”与“使用已构造会话”分开。产品流程接收该会话，测试不调用 USB／串口打开函数。仅把接入所需函数泛型约束保持为现有 `QdlChan`，不增加协议框架。
4. 存储函数的输入和输出另用故障 `Read`／`Write` 实现。分别测试可继续的短读短写、提前 EOF、零进展和硬错误。协议传输短写只有在后端语义允许时续传。最终数据未完整传输时不得报告成功。
5. fork 的 `qdl/src/lib.rs` 新增窄函数 `select_and_open(keys, requested, open)`。`keys` 是已枚举的稳定设备标识列表，`requested` 是可选精确标识，`open` 是接收索引的单次闭包。只有一个精确匹配时才调用 `open`。缺少选择、无匹配或多个匹配时返回错误，调用次数必须为零。USB／串口实际打开路径共用此函数，测试传入只记次数的闭包。该测试不证明主机驱动可用。
6. 生产会话禁用释放时重置。回归用例检查错误路径和 Drop 后的完整命令记录。丢失最终写 ACK、写入 NAK 或验证不一致后，记录中不能出现后续 program、patch、启动单元设置或 reset。显式重启只在前述策略允许时出现一次。

USB 后端已有按物理位置打开的入口，可保留并接入统一选择检查。测试不要求重新设计设备发现，也不复用默认选择第一台的路径。[USB 入口依据](https://github.com/qualcomm/qdlrs/blob/75fe2f7e42546a1d75969040378d4616419a9dcf/qdl/src/usb.rs#L166-L185)

### 目录与分区映射契约

命名和匹配规则由 `src/storage.rs` 共享，备份和恢复不得分别实现不同规则。

| 输入或输出 | 首版规则 |
| --- | --- |
| 分区镜像 | `lun<N>/<partition>.bin`。`N` 是十进制 LUN，不带多余前导零。名称必须与当前 GPT 分区名精确匹配，不做大小写转换 |
| 可用于目录的分区名 | 限 ASCII，匹配 `[A-Za-z0-9][A-Za-z0-9_.-]*`，不能以点结尾。首个点前的名称不能是 Windows 保留设备名：CON、PRN、AUX、NUL、COM1–9、LPT1–9，检查时不区分大小写 |
| 名称冲突 | 同一 LUN 内，同名或仅大小写不同的选中名称均视为冲突。备份将冲突项报不支持，不覆盖、不改名。恢复拒绝同一 LUN 内名称不唯一的目标，不增加按序号或 GUID 恢复入口 |
| GPT 捕获 | 保存为 `lun<N>/.gpt/primary.bin` 和 `lun<N>/.gpt/backup.bin`。保存实际读取的主备 GPT 原始字节。它们不属于目录恢复候选，不据此证明源目标布局一致 |
| 未完成文件 | 正式文件路径后追加 `.partial`。分区镜像和 GPT 捕获都使用此规则。目录恢复忽略这些文件 |
| 本工具生成的目录 | 只扫描根目录下一层 `lun<N>`，再扫描其中直属的 `.bin` 普通文件。不递归扫描 `.gpt` 或其他目录。省略 `--lun` 时使用目录中存在的所有 LUN，指定时只过滤该 LUN，绝不改写目录的 LUN 含义 |
| 普通平铺镜像目录 | 接受直属的 `<partition>.bin`。必须提供 `--lun`。`--from` 直接指向某个 `lun<N>` 子目录时，也按此规则处理，不从目录名称推断目标 |
| 混合布局 | 根目录同时有候选 `.bin` 和 `lun<N>` 子目录时，报输入错误。其他扩展名和非候选目录不参与恢复 |
| 分区过滤 | `--partition` 按原分区名精确过滤。嵌套目录中不同 LUN 的同名镜像各自对应所在 LUN。显式选择的分区缺文件、候选集为空、目标分区不存在或映射冲突时，首次写入前报输入错误 |

目录命名限制不限制单镜像源文件名。`--partition <name> --image <file>` 使用用户给出的原分区名。省略 `--lun` 时，该名称必须在已发现单元中唯一。指定时，只在该单元内匹配。名称包含路径字符但目标唯一时，可使用这一方式恢复。同一 LUN 内重名仍报不支持。

回归用例覆盖普通目录往返、路径字符、大小写冲突、同 LUN 重名、跨 LUN 同名、GPT 文件排除、`.partial` 排除和缺少所选文件。每个被接受的镜像必须得到唯一目标。任何目录恢复预检失败时，命令记录中不得出现写入。

### 结果契约

最终 JSON 对象使用以下字段。没有适用值的标量写 `null`，数组写 `[]`。文本输出从同一结果对象生成。偏移和字节数采用十进制字符串，避免消费者丢失整数精度。

| 字段 | 定义 |
| --- | --- |
| `command`、`verify_mode` | 五入口之一，以及 `best-effort`／`required`／`none`。备份和不支持的 unlock／lock 使用 `verify_mode: null` |
| `target` | 已选目标的 `device`、`backend`、`memory`、`luns`。未知标量为 null，尚未确定的 LUN 列表为 []。未选择目标时整个对象为 null |
| `coverage` | `limited` 和 `reason` 表示是否存在已知的扫描范围限制。未知覆盖范围使用 `limited: true`。不把已扫描范围成功解释为全设备成功 |
| `candidates` | 未选择设备时列出的稳定标识字符串。其他情况为空数组。无选择时返回 `input_error`，不上传加载器 |
| `status` | 下述六种命令结果之一。只有 `success` 使用零退出码，其他类别使用各自非零常量 |
| `items` | 按实际操作顺序列出分区／GPT 读取、program、patch 和请求的最终动作。每项 `id` 是本次命令内从 1 开始的顺序号，不是持久化作业标识 |
| 项目标识 | `operation` 为 `read`／`program`／`patch`／`set_bootable`／`reboot`。另含 `lun`、`partition`、`source`。`source` 是输入或备份输出路径，XML 操作附 `xml_node`，按文件内节点从 1 编号 |
| 项数据范围 | `start_byte` 是目标起点，`source_bytes` 是源文件长度，`partition_bytes` 是已定位分区大小。`transfer_bytes` 是本次应传输的数据总量，包含补零和 FILL 展开，排除 DONT_CARE。`transferred_bytes` 是主机 I/O 已接受的数据量，不证明设备已写入。未知值为 null，`reason` 保留表达式或未知原因 |
| `execution` | `done` 表示操作的协议阶段完成，不代表验证通过。`failed` 表示操作失败或未完成。另有 `skipped` 和 `not_attempted` |
| `write` | `acknowledged`／`failed`／`unknown`／`not_attempted`／`not_applicable`。适用于所有修改操作的确认结果，读取用 `not_applicable`。NAK 表示失败，不表示撤销已写字节 |
| `verification` | `matched`／`incomplete`／`mismatch`／`not_requested`／`not_applicable`。已确认写入的验证结果与 `write` 分开。读取、最终动作、未执行项和没有最终有效写入范围的项用 `not_applicable` |
| `ranges` | 验证范围数组。每段含 `start_byte`、`length_bytes`、`verification`、`reason`。只按连续结果区间汇总，不生成逐块记录。位置未知时两个数值可为 null，必须给出原因 |
| `reason`、`errors` | `reason` 说明跳过、未尝试或未验证的原因。`errors` 的元素含 `category` 和 `message`。`category` 使用非成功退出类别。项内记录该项错误，顶层只记录无法归属某项的错误 |

已确认写入若存在不一致范围，项的 `verification` 为 `mismatch`。否则，有任一未验证范围时为 `incomplete`。该项最终仍生效的范围全部匹配时才是 `matched`。存在最终有效写入范围但选择 `none` 时，使用 `not_requested`，不能表示已验证。无法确认的修改不启动验证，`verification` 使用 `not_applicable`。不能用回读结果替代缺失的写 ACK。

`MutationFailure::NotSent` 映射为 `write: not_attempted`，同时记录导致执行失败的原始原因。`Rejected` 映射为 `write: failed`，`Unknown` 映射为 `write: unknown`。这些修改失败都使用 `execution: failed`。单纯的预检拒绝和因前项停止而未启动的操作使用 `execution: not_attempted`。

命令结果收集项内和顶层错误，并按以下优先级汇总。低优先级事实仍保留，不因汇总而删除。

| 优先级 | `status` | 条件 |
| --- | --- | --- |
| 1 | `unknown_write` | 任一可能已执行的修改缺少最终确认，包括写入、补丁、启动单元设置或重启 |
| 2 | `execution_failed` | 任一实际操作明确失败，或回读不一致。备份读取失败也归此类 |
| 3 | `input_error` | 文件、参数、选择或映射无效。可预检的错误必须在首次修改前报告 |
| 4 | `unsupported` | 所选功能、目录命名或 `required` 预期内容不受支持。不能安全命名的备份项可与成功项并存，整体仍为不支持 |
| 5 | `verification_incomplete` | 已确认写入未完成所请求的验证。`best-effort` 允许继续不等于返回成功 |
| 6 | `success` | 没有上述错误。普通跳过项可存在，但必须列出原因，不能据此声明整包兼容或固件可启动 |

`not_attempted` 继承导致停止的原因，不额外升级结果类别。非 DISK 补丁和空文件名条目为 `skipped`，不算写入成功，也不单独导致失败。已知依赖本地变换的包仍在首次修改前报不支持。刷写若只剩跳过项且没有任何可执行操作，则报不支持。`--verify none` 的成功只表示操作已确认。

例如，下列恢复已写入 4096 字节，但读请求收到 NAK。目标分区剩余 4096 字节未覆盖。`best-effort` 可以继续处理下一项，最终退出类别仍为验证未完成：

```json
{
  "command": "restore",
  "verify_mode": "best-effort",
  "target": {"device": "usb:1:2", "backend": "usb", "memory": "ufs", "luns": [0]},
  "coverage": {"limited": false, "reason": null},
  "candidates": [],
  "status": "verification_incomplete",
  "items": [{
    "id": 1, "operation": "program", "lun": 0, "partition": "example",
    "source": "backup/lun0/example.bin", "xml_node": null,
    "start_byte": "1048576", "source_bytes": "4096",
    "transfer_bytes": "4096", "transferred_bytes": "4096", "partition_bytes": "8192",
    "execution": "done", "write": "acknowledged", "verification": "incomplete",
    "ranges": [{"start_byte": "1048576", "length_bytes": "4096", "verification": "incomplete", "reason": "read_refused"}],
    "reason": "read_refused",
    "errors": [{"category": "verification_incomplete", "message": "写入已确认，读请求被拒绝"}]
  }],
  "errors": []
}
```

测试必须断言混合成功／失败的备份、跳过本地补丁、验证未完成、验证不一致和丢失 ACK 的汇总结果。程序错误消息可以变化，类别、字段和状态含义保持一致。这里只定义运行结果，不保存计划或持久化日志。

### 最小命令契约

公共设备参数为 `--device`、`--backend usb|serial`、`--loader`、`--memory emmc|ufs`，以及必要的 `--lun`、`--sector-size`。扇区大小可沿用参考工具的介质默认值并显示，用户可显式指定；有设备返回值时检查冲突，不把默认值声称为实测值。无设备选择时只列出候选，不上传加载器。

- `backup --output <dir> [--partition <name> ...]`：省略 `--lun` 时选择全部已发现单元。缺省备份这些单元的全部已列出分区，多单元目录分开保存。
- `restore --from <dir> [--partition <name> ...]`：按目录映射契约选择现有镜像。平铺目录必须给出 `--lun`。也支持 `--partition <name> --image <file>`，与 `--from` 互斥。
- `flash --program <xml> ... --patch <xml> ...`：允许多个 XML；`--set-bootable <lun>` 和 `--reboot` 为明确可选动作。
- `restore`／`flash` 使用 `--verify best-effort|required|none`，缺省 best-effort。模式语义遵守前述表格。展示具体文件、目标、跳过项和验证限制后确认一次。非交互可用 `--yes`，不需要计划哈希。
- `--json` 仅改变输出；`--overwrite` 只控制备份目标文件覆盖，不绕过输入和协议错误。
- `unlock`／`lock` 在没有具体机型实现时返回不支持，不要求用户走一套不可完成的协议阶段。

不提供 `--plan-out`、`--apply-plan`、`--approve-plan`、`--resume`、资源数据库或专用清单导入。后续若确有需求，再单独设计；不能在实现时恢复为首版前提。

### 实施顺序与验收

1. 后续创建 `LanceaKing/qdlrs`，从固定提交增加测试接入和缺陷回归，再修复协议路径。完成条件：fork 原有工作区可构建，`firehose_io`、`sahara_transfer`、`selection` 离线测试通过。
2. 建立产品入口、薄适配层、GPT 和单分区读写基础。完成条件：产品可构建，`tests/cli.rs` 和单分区读取用例通过。尚未接入完整停止与验证策略的 restore／flash 入口返回不支持，不暴露半成品写入路径。
3. 增加目录备份、恢复映射、XML 和稀疏镜像解析。完成条件：目录与解析用例通过，候选操作及跳过项可测试。公共写入入口继续返回不支持，直到下一阶段完成。
4. 接通写入、三种验证模式、停止策略、最终动作和结果输出。完成条件：全部产品测试通过，默认模式为 best-effort，未知机型的 unlock／lock 仍返回不支持。
5. 在 Windows、macOS、Linux 上运行格式检查、Clippy、构建和离线测试。完成条件：锁定依赖的全部检查通过，JSON 标准输出无库日志污染。
6. 后续另行授权实机测试，分别验证连接、读取、恢复／刷写和回读。记录设备、加载器、固件、主机及后端。该记录只支持实测组合，不能推广为通用机型支持。

阶段 1–4 每阶段均须构建并运行该阶段已有测试。中间版本保留明确的不支持返回值，不以空成功代替未实现功能。离线用例至少断言下列行为：

| 用例 | 必须观察到的结果 |
| --- | --- |
| 可继续的短读短写 | 完成全部预期字节和最终 ACK 后才能成功。提前 EOF、硬错误或零进展不得报告完整传输 |
| 丢失最终 ACK、修改 NAK | 分别记录未知修改和明确失败。后续 program、patch、启动单元设置和 reset 的发送次数均为零 |
| `best-effort` 拒读 | 保留写入确认。完整 NAK 且会话正常时可以继续，最终结果为验证未完成 |
| `required` 未知预期内容 | 首次修改前报不支持，所有修改命令的发送次数为零 |
| `required` 运行时拒读 | 停止后续动作。已确认写入保持确认状态，验证结果未完成 |
| 验证读取超时或协议失步 | best-effort 和 required 都停止。已确认写入保持确认状态，验证结果未完成 |
| 修改阶段失步或断连 | 任一模式均停止。可能已发送请求但无最终确认时，结果为未知修改，不启动验证 |
| 回读不一致 | 返回执行失败，不执行剩余修改或最终动作 |
| `none` | 不发送验证读取。结果明确标为未请求验证 |
| 短镜像与稀疏数据 | 只写源数据及允许的扇区尾部补零，且不超出分区。DONT_CARE 不写零。重叠区间按最后写入验证 |
| 目录和结果混合 | 映射失败时不写入。备份缺失项保留错误，不能汇总为成功。GPT 捕获和 `.partial` 不进入批量恢复 |
| 最终动作 | 条件满足且用户显式请求时，各执行一次。被停止策略阻断时标记未尝试 |

不为移出首版的清单、哈希链和保存计划编写测试。

构建与测试命令为 `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace --all-features --locked` 和 `cargo build --workspace --all-features --locked`。设计评审时未执行代码构建或设备验证；第一阶段实际执行结果见[实施记录](../implementation/phase-1.md)。

## 保留的限制与后续事项

- 首版普通镜像没有来源和完整性证明；能写入不代表它来自同一设备或能启动。
- 本地补丁跳过沿用参考边界，不新增自动依赖证明。依赖本地变换的包不在支持范围内，首版不能自动识别所有这类依赖。
- 默认尝试回读不是写入原子性、回滚或断点续作机制；中断结果需如实报告。
- RMX3800 加载器接受情况、unlock／lock 方法、fastboot 自动化及实际跨平台设备支持仍需后续证据。
- 原简报中被本次范围调整移出的功能不是首版验收条件；不能以缺少这些额外机制为由继续阻塞基本操作。
